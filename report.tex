\section{Setup and Environment}
Single complex technical policy PDF \texttt{NITI\_AI\_Strategy.pdf} (114 pages, 109 with text). Same chunked corpus for both pipelines. LLM: Gemini API, \texttt{models/gemini-3.8-flash} for final answers (\texttt{gemini-flash-lite-latest} used briefly when 3.8 free-tier quota of 20 req/day was hit; same prompt and same model within each Answer~1 vs Answer~2 comparison). Key in Kaggle Secrets, never hardcoded. Embeddings: \texttt{all-MiniLM-L6-v2} (Bi-Encoder, 384 dim). Env: Kaggle \texttt{rag\_assignment}, GPU T4 x2, Internet ON. PDF added as Kaggle Input dataset since direct \texttt{wget} from \texttt{niti.gov.in} gives 403 Forbidden. Chunking run once and reused: 1000 chars, 150 overlap, skip under 200 chars, giving 362 chunks with id and page (sample \texttt{p4\_5} page 4).
\begin{lstlisting}[language=Python]
from pypdf import PdfReader
pdf_path = "/kaggle/input/datasets/pailatejeswararao/niti-ai-strategy/NITI_AI_Strategy.pdf"
reader = PdfReader(pdf_path)
pages = [(i, (p.extract_text() or "").strip()) for i, p in enumerate(reader.pages)]
pages = [(i, t) for i, t in pages if t]
chunks = []
for pi, txt in pages:
    s = 0
    while s < len(txt):
        part = txt[s:s+1000].strip()
        if len(part) > 200:
            chunks.append({"id": f"p{pi:03d}_{len(chunks):04d}", "page": pi, "text": part})
        s += 1000 - 150
\end{lstlisting}

\section{Two-Stage Retrieval Implementation}
\textbf{Pipeline 1 Baseline.} (a) Encode 362 chunks, L2-normalize, FAISS \texttt{IndexFlatIP} for cosine (shape $362\times384$, total 362). (b) Per query encode, normalize, search Top~10. (c) Top~3 directly into fixed prompt for Answer~1.
\begin{lstlisting}[language=Python]
from sentence_transformers import SentenceTransformer
import faiss, numpy as np
model = SentenceTransformer("all-MiniLM-L6-v2")
vectors = model.encode([c["text"] for c in chunks], batch_size=32, convert_to_numpy=True)
norm = vectors / np.linalg.norm(vectors, axis=1, keepdims=True)
index = faiss.IndexFlatIP(norm.shape[1]); index.add(norm.astype("float32"))
def search_top10(query):
    q = model.encode([query], convert_to_numpy=True)
    q = q / np.linalg.norm(q, axis=1, keepdims=True)
    scores, ids = index.search(q.astype("float32"), 10)
    return [{"rank": r+1, "id": chunks[int(ids[0][r])]["id"], "page": chunks[int(ids[0][r])]["page"],
            "score": float(scores[0][r]), "text": chunks[int(ids[0][r])]["text"]} for r in range(10)]
\end{lstlisting}
\textbf{Pipeline 2 Re-Ranking.} (a) Reuse same Top~10. (b) Score 10 pairs with Cross-Encoder \texttt{ms-marco-MiniLM-L-6-v2}. (c) Sort descending, take new Top~3. (d) Identical prompt and LLM for Answer~2, only chunks differ.
\begin{lstlisting}[language=Python]
from sentence_transformers import CrossEncoder
reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")
def rerank_top10(query, hits):
    scores = reranker.predict([[query, h["text"]] for h in hits])
    for i, h in enumerate(hits): h["cross_score"] = float(scores[i])
    return sorted(hits, key=lambda x: x["cross_score"], reverse=True)
from kaggle_secrets import UserSecretsClient
import google.generativeai as genai
genai.configure(api_key=UserSecretsClient().get_secret("newkey3"))
llm = genai.GenerativeModel("models/gemini-3.8-flash")
def make_prompt(query, top3):
    ctx = "".join([f"\nChunk {i+1}:\n{top3[i]['text']}\n" for i in range(3)])
    return ("You are a helper for NITI AI strategy document.\nAnswer only from given context.\n"
            f"If answer is not in context, say not found.\n\nContext:\n{ctx}\nQuestion: {query}\nAnswer:")
def get_answer1(query):
    hits = search_top10(query); top3 = hits[:3]
    return top3, llm.generate_content(make_prompt(query, top3)).text
def get_answer2(query):
    hits = search_top10(query); ranked = rerank_top10(query, hits); top3 = ranked[:3]
    return hits, ranked, top3, llm.generate_content(make_prompt(query, top3)).text
\end{lstlisting}
Top~10 cosine scores are close (0.55--0.58), so Bi-Encoder ranking is weak and re-ranking matters.

\section{Analysis and Report}
\textbf{Architecture.} Bi-Encoder encodes query and chunk independently, then cosine; precomputed once, fast, but no interaction, so it fails on synonyms (COREs) and negation. Cross-Encoder encodes (query, chunk) jointly with self-attention and scores relevance directly; no precompute, slow but context-aware. Hence retrieve-then-rerank: Top~10 fast, then careful read of 10. \\
\textbf{Qualitative.} Strict prompt says not found instead of inventing, so faults were omission (Q1, Q2 missed INR and workforce clauses at ranks 4--8) and noisy merging with duplicates (Q3: 8 vs correct 4). Re-ranking restored all three. \\
\textbf{Latency} (T4 x2, mean of 5, 362 chunks): baseline Top~10 0.0081\,s; re-rank 10 pairs extra 0.0382\,s (about $5\times$); retrieval total 0.0463\,s; Pipeline~1 with LLM 0.377\,s; Pipeline~2 with LLM 0.467\,s; extra end-to-end about 0.09\,s. LLM dominates; retrieval overhead is small. \\
\textbf{Scaling.} Cross-Encoder needs a full forward pass per pair with nothing precomputable. 10 pairs cost 38\,ms here, so 362 chunks would cost about 1.4\,s per query and lakhs of chunks hours per query. Bi-Encoder vectors are precomputed with fast FAISS search. So prefilter to 10 then re-rank gives speed plus accuracy (8\,ms to 46\,ms retrieval for Not found to Found).
