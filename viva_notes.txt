Step 8 - Basic RAG Structure Confirmed
Date: 12 Oct night
Basic RAG flow in our code:
1. Query comes from user.
2. Get context: search_top10 changes query to vector and searches FAISS index. Returns Top 10 chunks with rank, id, page, score.
3. Take Top 3 chunks as context. For Pipeline 1 we take old Top 3 directly. For Pipeline 2 we re-rank first with rerank_top10 and then take new Top 3.
4. Make prompt: make_prompt joins the 3 chunk texts as context plus query. Prompt says answer only from context, else say not found.
5. Get answer: llm.generate_content sends prompt to gemini-3.8-flash. If info is in chunks, it answers. Else it returns not found or sorry not found.
This matches assignment rule of identical prompt, only chunks differ.

Step 19 - Report Section 1 Started
Date: 13 Oct
Section 1 Architecture Comparison: need short note on Bi-Encoder vs Cross-Encoder.
Points to cover:
- Bi-Encoder encodes query and chunk separately, then cosine. Fast, precompute, but misses word interaction, fails on negation and synonyms like COREs.
- Cross-Encoder takes query plus chunk together, joint attention across tokens, scores relevance directly. Slow, cannot precompute, but understands context, fixes negation and trap.
- Our code: all-MiniLM-L6-v2 for Bi, ms-marco-MiniLM-L-6-v2 for Cross. FAISS IndexFlatIP for fast Top 10, then Cross for Top 10 only.
- Link to results: baseline 8 ms, re-rank 38 ms extra. Rank shifts prove difference.
